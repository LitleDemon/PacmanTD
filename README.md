# Техническое задание: Tower Defense в сеттинге Pac-Man

**Проект:** учебный 2D Tower Defense
**Движок:** Unity (2D, LTS-версия)
**Команда:** 2 человека (A и B)
**Ориентировочный срок:** 5 недель при 10–15 ч/неделю на человека
**Итоговый артефакт:** играбельный билд с 3 уровнями, полным игровым циклом (старт → волны → победа/поражение → рестарт)

---

## 1. Цель и концепция

Создать классический 2D Tower Defense с полным игровым циклом, используя сеттинг Pac-Man как визуальную и структурную основу. Ключевая особенность: **зона строительства башен — это лабиринт**, а маршрут врагов (дом призраков → Пакман) отделён от неё. Количество уровней равно количеству путей: уровень 1 — один путь, уровень 2 — два, уровень 3 — три.

Узнаваемость сеттинга достигается цветами и силуэтами (жёлтый Пакман, четыре цветных призрака, синие стены лабиринта), без сложной детализации арта. Допускается использование примитивов и простых спрайтов, нарисованных вручную.

---

## 2. Объём работ (Scope)

### Входит в MVP
1. Три уровня с конфигурируемым количеством путей (1, 2, 3).
2. Лабиринт-зона строительства с фиксированными слотами под башни.
3. Четыре типа врагов (призраки: Блинки, Пинки, Инки, Клайд) с разными статами.
4. Два типа башен (одиночная цель и AoE).
5. Волны врагов с настраиваемыми параметрами (тип, количество, интервал, путь).
6. Экономика: пеллеты за убийство врагов, стоимость башен.
7. Система жизней (3 жизни Пакмана).
8. UI: счётчики пеллет и жизней, панель выбора башни, кнопка старта волны, экраны победы/поражения.
9. Рестарт уровня и переход между уровнями.

### Не входит (out of scope)
- Продвинутый AI призраков (chase/scatter/frightened).
- Power Pellet как игровая механика (только опциональный бафф, если останется время).
- Звуковое сопровождение (опционально на этапе полировки).
- Меню настроек, сохранения, таблица рекордов.
- Мобильная версия, геймпад.

## 4. Архитектура и общие контракты

Эти сущности фиксируются в первую неделю и не меняются без согласования обеих сторон.

### 4.1. Ключевые типы данных

```csharp
// Assets/_Project/Scripts/Core/

public interface IDamageable
{
    void TakeDamage(float amount);
    bool IsAlive { get; }
}

public static class GameEvents
{
    public static event Action<int> OnPelletsChanged;
    public static event Action<int> OnLivesChanged;
    public static event Action OnGameOver;
    public static event Action OnLevelCompleted;
    public static event Action OnWaveCompleted;
}

[CreateAssetMenu(menuName = "TD/Path Config")]
public class PathConfig : ScriptableObject
{
    public string pathID;
    public Vector2[] waypoints;
}

[CreateAssetMenu(menuName = "TD/Level Config")]
public class LevelConfig : ScriptableObject
{
    public string levelName;
    public List<PathConfig> paths;
    public List<Wave> waves;
    public int startingLives = 3;
    public int startingPellets = 100;
}

[System.Serializable]
public class Wave
{
    public GameObject enemyPrefab;
    public int count;
    public float spawnInterval;
    public string targetPathID; // пусто = случайный путь
}
```

### 4.2. Публичные API между зонами ответственности

| Метод / свойство | Владелец | Кто вызывает |
|---|---|---|
| `GameManager.AddPellets(int)` | B | A (при смерти врага) |
| `GameManager.SpendPellets(int): bool` | B | B (при постройке башни) |
| `GameManager.LoseLife()` | B | A (когда враг дошёл до Пакмана) |
| `Spawner.StartNextWave()` | A | B (по кнопке UI) |
| `BuildManager.TryBuildAt(slot, towerType)` | B | B (по клику) |
| `IDamageable.TakeDamage(float)` | A (реализация) | B (снаряды башен) |

### 5.2. Детально по зонам ответственности

**Человек A — Боевая система**
- Реализация движения врагов по waypoint'ам.
- Реализация `IDamageable` в `EnemyHealth` со смертью и начислением пеллет.
- Спавнер волн, читающий `LevelConfig.waves`.
- Распределение врагов по путям согласно `Wave.targetPathID`.
- Логика таргетинга башен (поиск ближайшего врага в радиусе) — в `TowerAttack`.
- Снаряды: движение, попадание, вызов `TakeDamage`.
- Достижение врагом финальной точки → вызов `GameManager.LoseLife()`.
- Спрайты призраков (4 цвета) и снарядов.
- Тестовая сцена `Test_Enemies`.

**Человек B — Мир, экономика, UI**
- Разметка лабиринта в Tilemap (стены, коридоры, слоты под башни).
- `BuildSlot` и `BuildManager`: проверка занятости, списание пеллет, установка башни.
- Класс `Tower` (статы, визуал, размещение).
- `GameManager`: пеллеты, жизни, переходы состояний (игра/победа/поражение).
- `LevelLoader` и `LevelConfig` для всех трёх уровней.
- UI: счётчики, панель башен, кнопка «Старт волны», экраны win/lose, рестарт.
- Тайлы лабиринта, спрайты башен и Пакмана, анимация рта Пакмана.
- Тестовая сцена `Test_Build`.

**Совместно**
- `Core/`: `IDamageable`, `GameEvents`, структуры данных.
- Сборка `Main`-сцены (по очереди, не одновременно).
- Финальный баланс (HP/скорость врагов, стоимость/урон башен, количество волн).
- Плейтесты и багфикс.

## 7. Правила работы с Git

1. **Папки-владельцы.** A работает только в `Scripts/Enemies`, `Scripts/Waves`, `Prefabs/Enemies`, `Data/Paths`, `Scenes/Test_Enemies`, `Art/Enemies`. B — в `Scripts/Towers`, `Scripts/Building`, `Scripts/UI`, `Prefabs/Towers`, `Data/Levels`, `Scenes/Test_Build`, `Art/Environment`.
2. **`Core/` и `Main`-сцена** — только по согласованию, не одновременно.
3. **`.meta`-файлы коммитятся всегда**, `Library/`, `Temp/`, `Obj/`, `Build/`, `Logs/`, `UserSettings/` — исключены через `.gitignore`.
4. **Ветки живут 1–3 дня максимум**, ежедневный push, частые merge.
5. **Префабы вместо правок в сцене**: изменения в поведении — через префаб, а не через переопределение в `Main`.
6. **ScriptableObject-ассеты** редактирует только владелец (A — пути, B — уровни). Изменение структуры — через обсуждение.

## 8. Риски и митигация

| Риск | Вероятность | Митигация |
|---|---|---|
| Конфликты в `Main`-сцене | Высокая | Свои `Test_*`-сцены, `Main` — по очереди, сборка из префабов |
| Рассинхрон архитектуры после недели 1 | Средняя | Жёсткая фиксация контрактов в `Core/`, code review перед merge |
| Затягивание с артом | Средняя | Заглушки (квадраты/круги) до недели 3, финальный арт — на неделе 3 |
| Баланс съедает время | Высокая | Все статы в ScriptableObject, менять без перекомпиляции, итерации на неделе 4–5 |
| Один человек становится бутылочным горлышком | Средняя | Кросс-ревью, оба умеют делать и код, и заглушки арта |
